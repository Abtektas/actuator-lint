# SDF001: the world loads its own systems but not one that a sensor of the model needs

Level: error. Runs with `--sdf` and `--world`.

## What it checks

The world file given with `--world` declares at least one `<plugin>` of its
own, and among them is not the gz-sim system that a sensor of the model needs:

| Sensor type in the model | System |
|---|---|
| `imu` | `Imu` |
| `air_pressure` | `AirPressure` |
| `magnetometer` | `Magnetometer` |
| `navsat` | `NavSat` |
| `air_speed` | `AirSpeed` |
| cameras and GPU lidars | `Sensors` |
| always | `Physics` |

## Why it matters

gz-sim loads its server configuration file only when the world loads no system
itself (`SimulationRunner.cc` of gz-sim 8: "No systems loaded from SDF, loading
defaults"). PX4 points that file to its own `server.config`, which has all the
systems above. A world that declares any plugin, for example only `Physics`
and `Sensors`, therefore loses the others, and the model's sensors publish
nothing. PX4 then has no gyro, accelerometer or barometer data and does not
arm. The PX4 worlds declare no plugins, so they are not affected; worlds
copied from Gazebo examples often are.

This is the failure of [PX4 forum thread 48506](https://discuss.px4.io/t/48506).
A world that declared `Physics`, `UserCommands`, `SceneBroadcaster` and
`Sensors` gave the same preflight failures with PX4's x500 in SITL.

## What to do

Add the systems the finding names to the world, as in PX4's `server.config`,
or remove all `<plugin>` elements from the world so that gz-sim loads the
server configuration.
