# SDF002: a sensor that PX4 reads in simulation is missing from base_link

Level: error, or warning when the parameters turn the sensor off. Runs with `--sdf`.

## What it checks

The PX4 gz bridge (`GZBridge.cpp`) subscribes to sensors by link and sensor
name: `imu_sensor`, `air_pressure_sensor`, `magnetometer_sensor` and
`navsat_sensor` on the link `base_link` (a name followed by `_` and a number
also counts). The rule reports each one the model does not have.

It is not reported when PX4 simulates the sensor itself (`SENS_EN_BAROSIM`,
`SENS_EN_MAGSIM` or `SENS_EN_GPSSIM` set to 1). It is a warning instead of an
error for the GPS when `SYS_HAS_GPS` is 0 and for the magnetometer when
`SYS_HAS_MAG` is 0.

## Why it matters

A sensor with another name, or on another link, publishes on a topic the
bridge does not read, so PX4 gets no data from it. With the IMU renamed to
`imu_main`, PX4's x500 in SITL failed the preflight check ("No valid data from
Gyro 0", "No valid data from Accel 0") and did not arm.

## What to do

Name the sensors and their link as above, or set the parameters that tell PX4
the sensor is not there or is simulated by PX4.
