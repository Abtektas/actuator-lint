# CA030: a line of the parameter file could not be used

Level: error

## What it checks

A line of the input looks like a parameter but could not be used:

- the value is not a plain decimal number, for example `-0,05` with a comma,
  `nan`, `0x10` or `1_0`
- the name is not a valid PX4 parameter name
- the line does not have the form of its format, for example
  `CA_ROTOR4_PZ = -0.05` in a plain file, or fewer than five tab-separated
  fields in a QGroundControl export
- an integer parameter such as `CA_ROTOR_COUNT` has a value that is not an
  integer. This needs an engine built from tool version 0.4.0 or newer; older
  engines round the value

In a plain file and in a QGroundControl export every such line is reported. In
a PX4 airframe script only lines that set a `CA_*` parameter are, because other
parameters often get their value from a shell variable; those are listed under
"Notes".

## Why it matters

The parameter keeps PX4's default value, so the matrices and all other
findings are for another configuration than the one in the file. Without this
finding the report could look clean because of a typing mistake.

## What to do

Correct the line. Write numbers with a decimal point and without units. If the
line is not meant to be a parameter, turn it into a comment with `#`.
