# CA002: PX4 dropped a control axis

Level: error; warning for an axis the vehicle type does not need

## What it checks

PX4 reports that it removed an axis from the effectiveness matrix
(`ControlAllocation::getDroppedAxes()`). PX4 does this when the row of that
axis is a linear combination of rows with a higher priority. The priority
order is thrust_z, roll, pitch, thrust_x, thrust_y, yaw.

## Why it matters

A dropped axis is not controlled by this matrix. PX4 also reports this at run
time; this rule shows it before the vehicle is powered.

The finding is an error for an axis that [CA005](CA005.md) lists as needed for
the vehicle type, and for vehicle types the tool knows nothing about. It is a
warning for an axis the vehicle type does not need: PX4 `main` drops thrust_x
and thrust_y of its own airframe `5021_xplane_qtailsitter`, whose canted
rotors produce a little of both as a side effect of pitch and roll.

## Limits

PX4 v1.17.0 and release/1.18 do not have this check. With an engine built
against them the report says that CA002 was not checked, and the tool applies
the same test itself, see [CA006](CA006.md).

## What to do

Look at the effectiveness rows of the dropped axis and of the axes before it in
the priority order. Rotors that all lie on one line, or control surfaces with
identical torque values, are typical causes.
